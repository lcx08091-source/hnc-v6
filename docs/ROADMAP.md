# HNC 路线图

> 写于 v5.23.0-rc1(2026-10-02),同日修订:**HNC 6.0 暂缓**,当前只执行 5.x 计划表(§A)。
> 这是方向性规划,不是承诺;每一步都以真机实测结果为准,随时调整。版本号为预估,可能合并或拆分。

## A. 5.x 更新计划表(当前执行)

原则:**不做大重构、不换数据层、不改进程结构、不换界面**;每版都能单独发、单独回退;新逻辑先与旧逻辑并行对比,确认更好再切换。

| 版本 | 主题 | 内容 | 验收 / 需要你做的 |
|---|---|---|---|
| **v5.24** | DPI 3.0 地基 + 能量化(rc1:T1 本机样本采集 ✅) | 证据格式与融合框架;v1/v2 识别改写为插件(**新旧并行、以旧为准、记录差异**);**本机标签工厂**(本机前台 + UID 归属 → 带标签样本);**识别自评面板**(准确率 / 覆盖率 / 依据分布 / 最常错的应用) | 你正常用手机 1–2 天 → 第一份真实准确率报告 |
| **v5.25** | DPI 3.0 新识别器 | 启动指纹(冷启动 DNS 序列)、QUIC 传输参数指纹、HMM 前台(防来回跳、秒级切换)、规则库扩充(开源域名清单,目标数百个应用) | 前台切换延迟、来回跳次数、准确率对比 v5.24 |
| **v5.26** | DPI 3.0 自学习 | 交互节拍(人在用 vs 挂后台)、共现聚类发现新应用(FlowPrint 思路)、轻量分类器;确认更准后**新引擎转正、旧逻辑下线** | 长尾覆盖率提升;新应用可被自动发现 |
| **v5.27** | 稳定性(从 6.0 地基里提前做的低风险项) | **升级自检 + 自动回滚**(热点 / 限速 / WebUI 异常则退回上一版);**流量录制回放**(真机只录头部与元数据,离线回放做 DPI 回归);兼容性报告标准化(可选匿名导出) | 刷一次故意坏的包验证回滚;用你录的一段流量跑回放 |
| **v5.28** | 应用感知 QoS(初版) | 用识别结果给队列分优先级:通话 / 游戏 > 前台视频 > 浏览 > 后台下载;**默认关闭、可逐台开启**;先不做 QoE 闭环 | 开热点时一台打游戏、一台下载,看延迟抖动 |
| **v5.29** | 收尾与正式版 | 修真机反馈;瘦身(删 v5.26 下线的旧识别、合并重复的 shell);文档;**把 5.19 以来的 rc 收敛成一个正式版** | 真机全功能回归 |

不在 5.x 做(留给 6.0):SQLite 数据层、进程收拢、统一策略引擎、场景模式、新界面转正、多台管理、DPI 4.0 的会话理解 / QoE 闭环 / 异常检测。

**可选、待你决定**:精确模式助手 App(独立安卓工程)、匿名共享指纹库(需服务器)。

## 0. 现状(v5.23)

| 层面 | 现在怎么做 | 规模 / 局限 |
|---|---|---|
| 域名识别 | dpid 抓 DNS / TLS SNI / QUIC Initial(解密取 SNI)/ HTTP Host,对照规则库 | 189 个应用、1426 条域名后缀(`data/dpi_rules.json` + `data/dpi_rules.d/` 33 个文件),166 个实体 |
| TLS 指纹 | JA4;内置种子 + 本地学习(`fp_learn.go`,≥2 台设备 ≥20 次或单设备 ≥50 次、纯度 ≥90% 才启用,14 天半衰期) | 冷启动时几乎为空,要靠真机积累 |
| IP 归属 | `data/ip_owner.bin`,ASN → 机构 | 45 家机构 |
| 流量形态 | `flow_shape.go`,conntrack 计数的速率 / 包长 / 对称度 / 节奏 → 9 类 | 手工阈值,未用真实标签校准 |
| 前台推断 | `fg_model.go`,综合形态与多应用相对活跃度 | 准确率未实测 |
| 补漏 | 共现推断、VPN/代理识别、加密 DNS 策略、用户纠正(`dpi_correct`)、可选 DNS 接管 | — |

**核心问题**:各识别手段按硬优先级拼接,置信度互不可比;没有标准答案,**无法量化准确率**。

与商用 DPI(深信服 / 华为等)的差距是数量级的:应用库规模、私有协议深度解析、应用内子功能识别。HNC 的定位是「少而准、能自学、可纠正、可解释、全本地」,不追求规模对齐;**不做 SSL 中间人解密,不向他人设备注入或 hook**。

## 1. DPI 3.0:统一证据 + 融合 + 学习闭环(v5.24 – v5.26)

### 1.1 架构

```
采集层(dpid)       DNS · TLS SNI/JA4 · QUIC Initial/传输参数 · HTTP Host
                    conntrack 计数 · 本机 UID 归属 · 本机前台(dumpsys)
        │
证据层(插件)       每个识别器只产出证据 {flow|device, 候选 app, 概率, 依据}
                    域名规则 · JA4 · QUIC 参数 · IP 归属 · 启动指纹 · 流量形态
                    交互节拍 · 共现聚类 · 用户纠正 · 助手上报
        │
融合层              ① 单流:按各识别器实测可靠度加权合成后验概率
                    ② 设备时间线:HMM 推前台(隐状态 = 前台 app),平滑 + 快速切换
                    ③ 输出:app + 置信度 + 依据链 + 前台/后台
        │
学习回路            本机标签工厂 + 用户纠正 + 助手上报 → 带标签样本
                    → 更新指纹表 / 启动指纹 / 形态阈值 / 识别器可靠度
                    → 每日自评:准确率、覆盖率、最常错的应用
```

### 1.2 新识别手段

1. **本机标签工厂**(最高优先级):开热点的手机本身能拿到真值 —— root 下 `dumpsys activity` 得前台包名,本机流量可按 UID 归到包名。正常使用时自动产出「包名 → JA4 / QUIC 参数 / 启动 DNS 序列 / 流量形态」的带标签样本。同一 App 在其他安卓设备上通常使用相同的网络库,指纹可迁移。这同时是**第一次能量化准确率**的数据来源。
2. **启动指纹**:冷启动 / 切回前台的 1–2 秒内,App 按固定顺序查询一串域名(配置 → 统计 SDK → 自家 API → CDN)。即使使用共享 CDN 或 ECH,查询序列仍可区分 App;该事件本身也是秒级的「前台切换」信号。
3. **QUIC 传输参数指纹**:Initial 包已在解密,传输参数组合比 JA4 更能区分网络库版本。
4. **概率融合 + HMM 前台**:替代硬优先级;人不会每 10 秒换一次 App,HMM 自然抑制来回跳。
5. **交互节拍**:刷短视频 = 人的节奏(不规则大块下载),后台播放 / 下载 = 机器节奏(均匀持续),打字 = 上行零碎小包。区分「人在用」与「挂后台」。
6. **共现聚类发现新应用**(参考 FlowPrint,NDSS 2020):无标签地把「总在同一时间出现的目的地」聚成指纹,改进「新发现的应用」。
7. **轻量分类器**(参考 AppScanner,IEEE EuroS&P 2016):包长 / 方向统计 + 随机森林等小模型,样本来自标签工厂与纠正。ET-BERT(WWW 2022)类大模型只作参考,手机上不现实。
8. **精确模式助手(可选)**:被管控设备由机主自愿安装的小 App,经「使用情况访问权限」上报前台应用(与 Family Link 同原理)。只做 opt-in,iOS 不支持。
9. **规则库扩充**:导入开源域名清单(如 v2fly domain-list-community,MIT),目标数百个以上应用。

### 1.3 版本拆分

| 版本 | 内容 | 验收 |
|---|---|---|
| v5.24 · 地基 | 证据格式与融合框架;v1/v2 全部改写为插件,**新旧并行、以旧为准、记录差异**;本机标签工厂;自评面板(准确率 / 覆盖率 / 依据分布) | 真机跑 1–2 天得到第一份真实准确率 |
| v5.25 · 新识别器 | 启动指纹、QUIC 参数指纹、HMM 前台、规则库扩充 | 前台切换延迟、来回跳次数、准确率较 v5.24 提升 |
| v5.26 · 自学习 | 交互节拍、共现聚类、轻量分类器;(可选)助手 App | 长尾应用覆盖率提升;新应用可被自动发现 |

### 1.4 能做到 / 做不到

- 近期:主流应用的前台识别稳定、秒级切换;准确率有实测数字;安卓设备优于 iPhone(指纹可迁移)。
- 中期:未识别流量自动聚类成新应用;小模型提升「在干什么」的粗粒度分类。
- 天花板:不解密时,应用内子功能(如微信聊天 / 视频号)只能做到「在用微信 + 正在视频通话」这类粗粒度;私有 UDP 协议(游戏、语音)主要靠形态与归属。
- 不做:看到加密内容本身;追求商用级「数千应用 + 私有协议深度解析」。

### 1.5 开销与风险

- 重构量大于 v5.23,分三版、过渡期双轨运行。
- 无标签数据时 3.0 ≈ 2.0 的表现。
- 融合 / HMM 计算量小;学习回路低频运行,并遵循 v5.22 的活动档位降频。

## 2. HNC 6.0 地基(**暂缓**;其中升级回滚、录制回放、兼容报告已提前到 v5.27)

1. **数据层迁移 SQLite**:替代数十个 JSON 文件;版本化迁移、旧数据自动压缩、统计查询加速;根治并发写与文件损坏(v5.21 曾修 capabilities.json 损坏)。
2. **进程收拢**:httpd + dpid + hotspotd + 大量 shell → 一个 Go 主核心 + 必要的 shell(iptables / tc 调用)。更省电、故障点更少。
3. **流量录制回放**:真机只录头部与元数据,开发时离线回放做 DPI 回归测试,解决「只能真机验证」的瓶颈。
4. **安全升级与自动回滚**:升级后自检热点 / 限速 / WebUI,异常自动回退上一版。
5. **兼容性矩阵**:ROM / 内核 / root 方案探测标准化,可选匿名提交。
6. **稳定 API**:冻结 `/api/v1`;规则包、识别器插件可独立更新;支持社区规则包。
7. **隐私默认值**:日志与历史默认短期保留、可加密、一键清除;会记录访问内容的功能(DNS 查询日志等)默认关闭并明确标注。

## 4. DPI 4.0:从「识别」到「理解」(**暂缓**;应用感知 QoS 初版已提前到 v5.28)

1. **会话级理解**:「19:40 起刷短视频 35 分钟,其中直播 8 分钟」「王者荣耀第 3 局」「网课视频通话 45 分钟」;策略可写成「每天最多 2 局」「网课期间禁止其他应用」。
2. **体验感知(QoE)**:从加密视频流节奏推断画质档位与卡顿,从游戏上下行节拍估算延迟抖动;HNC 第一次知道「谁因拥塞 / 限速而卡」。
3. **应用感知智能 QoS**(闭环):识别结果驱动队列优先级(通话 / 游戏 > 前台视频 > 浏览 > 后台下载 / 更新),QoE 反馈自动调整。
4. **异常与隐私感知**:每台设备的行为基线(凌晨大量上传、新设备扫描局域网、后台定时外连 → 提醒);追踪器透明度与一键拦截。
5. **本地增量学习小模型**;(可选)匿名共享「指纹 → 应用」表,只共享指纹哈希,需服务器与隐私设计,是否做待定。

边界不变:不解密;所有推断带置信度、依据并可纠正。

## 5. 总路线

```
v5.24–5.26  DPI 3.0(地基 → 新识别器 → 自学习)   ← 准确率有实测数字
v5.27       升级回滚 · 录制回放 · 兼容报告(6.0 地基中的低风险项)
v5.28       应用感知 QoS 初版(默认关)
v5.29       收尾 → 5.x 正式版
——— 以下暂缓 ———
v6.0        SQLite · 进程收拢 · 策略引擎 + 场景 + 新界面 + 自动限速档
v6.1–6.x    DPI 4.0:会话理解 → QoE → 智能 QoS 闭环 → 异常 / 追踪器
```

顺序理由:DPI 4.0 的会话理解、QoE、智能 QoS 都建立在「识别准且可量化」之上,故 DPI 3.0 先行;策略引擎与数据层是新界面的底座,先做地基避免返工。

**若只做三件事**:① DPI 3.0 本机标签工厂 + 自评;② SQLite 数据层 + 录制回放;③ 应用感知智能 QoS。

**待决定**:匿名共享指纹库(需服务器)、原生配套 App / 精确模式助手(需独立 Android 工程)。
